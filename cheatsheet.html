The commands behind Who Broke Prod?, grouped by the question they answer. Click any command to try it in the sandbox below, a small simulated repository running in your browser. Tags show which cases use each section.

What changed? (history)

Case 01Case 09
git log --onelineOne line per commit: short hash, refs, subject.
git log -n 5Only the 5 newest commits (also -5).
git log -- config/prod.ymlCommits whose diff touched that path. -- separates paths from revisions.
git log --all --onelineEvery branch and tag, not just HEAD. Includes work that never shipped.
git log main..featureCommits on feature that aren't on main.
git log --stat / -pWhich files changed / the full diffs.
git log --since=2026-10-28 --until="2026-10-29 18:00"A time window (committer date).
git show HEAD~2One commit's metadata and diff. git show REV:path prints a file as it was.
A directory (config/) or glob ('config/prod*') matches more than one file. Name the exact file when that's what you mean.

Who committed it?

Case 02
git log --author="Mira Chen"Regex on Name <email>. Matches anywhere: “Mira” also hits “Miranda”.
git log --author="^Mira C"Anchor the start of the string.
git log --grep=PAY-512Regex on the commit message. Add -i for case-insensitive.
git log --author=X --grep=YBoth must match (author AND message).
git shortlog -sneCommit counts per author, with emails.
People commit from several email addresses. Match on the name unless the email is the point.

When did this code appear or vanish? (pickaxe)

Case 03
git log -S"retryCharge("Commits that change how many times the string occurs: added or removed.
git log -G"timeout_ms"Commits with any added or removed line matching the regex, including in-place edits.
git log -S"x" -- src/Combine with a path.
git grep -n "retryCharge(" v2.4.0Search file contents at a revision.
-S ignores a commit that only edits the arguments of a call. -G includes it. Pick the one that matches your question.

Who wrote this line? (blame)

Case 04Case 05
git blame src/discounts.jsEvery line → the commit that last changed it.
git blame -L 14,19 FILEOnly lines 14–19. Also -L 14,+6.
git blame -L '/function applyDiscount(/,/^}/' FILERange from a regex to a regex.
git blame -L :applyDiscount FILEThe function whose definition matches. Watch for similar names.
git blame -w FILEIgnore whitespace-only changes (re-indents, tabs→spaces).
git blame --ignore-rev HASH FILEPretend a noisy commit never happened. In real repos: .git-blame-ignore-revs.
git blame REV -- FILEBlame as of an older revision.
cat -n FILEFind line numbers first.

When did it break? (bisect)

Case 06Case 07Case 10
git bisect start BAD GOODe.g. git bisect start main v2.4.0. Git checks out the midpoint.
git bisect good / badMark the checked-out commit after testing it.
git bisect skipCan't be tested (doesn't build). Neither good nor bad.
git bisect run CMDAutomate: exit 0 = good, 125 = skip, 1–127 = bad.
git bisect view / logRemaining suspects / marks so far.
git bisect resetFinish and return to where you started.
A failing build isn't evidence about the bug. If you mark it bad, bisect blames the commit that broke the build instead. Wrap your test in a script that exits 125 when the build fails.

Where did my commits go? (reflog)

Case 08Case 10
git reflogEvery position HEAD has had: commits, amends, resets, checkouts. Newest first.
git show HEAD@{4}Inspect an entry.
git reset --hard HEAD@{4}Move the current branch back to it.
git branch rescue HASHGive a lost commit a name (safe: moves nothing).
git branch -f release/2.5 HASHMove another branch without checking it out.
git reset --hard ORIG_HEADUndo the last reset.
HEAD@{n} numbers shift every time HEAD moves, including your own checkouts. Copy the hash.

Ship only the fix (cherry-pick)

Case 09Case 10
git switch release/2.5Go to the branch that should receive the fix first.
git cherry-pick A BCopy commits A then B onto HEAD as new commits.
git cherry-pick -x ARecord “(cherry picked from commit …)” in the message.
git cherry-pick A..BEverything after A up to B. Easy to drag in features.
git branch --contains HASHWhich branches already have a commit.
If fix B edits a line that fix A introduced, pick A first, or B conflicts.
